UI continuity (v2.6)

The shared mechanisms that make separate surfaces feel like one product: a single settings cog (theme + skin swatches + aesthetic), a data-driven app switcher, an opt-in shared theme cookie, and live cross-tab sync. All additive — nothing changes for existing consumers until they opt in.

Settings cog

Click the cog in the header. Theme is a light/dark/auto segmented control; the skin row renders swatches of each built-in skin’s own tokens (every swatch carries data-skin, so its color is that skin’s --accent over its --bg — never hardcoded). The aesthetic toggle flips polished ↔ hybrid. Mount it with: 

glacialMountSettings('#settings-mount');

App switcher

A data-driven launcher. Pass a list of services; each becomes a .glacial-tile with an optional status dot (green/yellow/red). The list below is placeholder data only.

Cross-surface config (opt-in)

Set these before glacial.js loads (window global or <meta>): 

<script>
  window.GLACIAL_SHARED_THEME  = true;            // one glacial-theme cookie, migrates old picks
  window.GLACIAL_DEFAULT_THEME = 'auto';          // follow OS preference (or 'light'/'dark')
  window.GLACIAL_DEFAULT_SKIN  = 'deep-navy';     // durable default skin (v2.7)
</script>

Live cross-tab sync (BroadcastChannel) is same-origin only. Cross-surface continuity now rides the URL-param appearance carry (v2.7) — v2.6’s GLACIAL_COOKIE_DOMAIN was removed (browsers reject single-label-TLD cookie domains).
