Layout: list → detail

When a user picks an item from a list, where does the detail show up? Three patterns, each with different tradeoffs around URL state, scroll position, and quick-edit speed.

2026 trend: master–detail / split-view is the gold standard for power users (email clients, Linear's issue list, Notion's database peek). Drawers are the consumer alternative.

D1 · Single page (current default) ↗
ProsShareable URLs · Browser back/forward · Simplest mental model
ConsLose list scroll · Slow comparison · Full reload per item
D2 · Split view (master-detail) ↗
ProsFast browse · No reload · Email-client familiar · ↑↓ to step through
ConsHalf the detail width · Mobile collapses · URL state harder
D3 · Drawer / bottom sheet ↗
ProsFull list visible · Quick preview/edit · Becomes bottom sheet on mobile
ConsCan't compare two items · No deep-link by default · Modal anxiety

My recommendation

For internal tools where you build, browse, and tweak rapidly: D2 (split-view) for power-user lists (catalog listings, project boards, directory records), D3 (drawer) for quick-edit cases (form approvals, inline edits, mobile-first). D1 (single-page) stays for content that benefits from shareable URLs — public listings, archive pages.
